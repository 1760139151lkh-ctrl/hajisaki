# 随手画室与照片批注

手机继续原提示词指定的 HUAWEI Pura 80 Pro、HarmonyOS 7 / API 26 工程，交付 HAP。源码属于 `phone/harmony/`；iPad 的后续开发仍在原对话和 `ipad/` 中进行。原始手机宪章与总验收台账继续有效。

## 使用路径

从首页“随手画室”或对话输入区“画室”打开草稿纸；从图片附件或档案“批注”打开原图。待发送图片的名称可重新打开批注，旁边的叉号只移出待发送附件。画室支持画笔、连续编号、矩形马赛克、顺时针旋转、拖动四角拉正及纸张增强。

笔迹直接绘在原生 Canvas 上。马赛克和图像变换由主机处理，实际图像用 ArkUI Image 显示，不依赖 ArkWeb 或桌面截图。变换作用于此前完整画面，包括已有批注；纸张增强会将画面转为增强对比的灰度。撤销和重做保留操作顺序。

“放回对话”先导出 PNG，再加入未发送附件；不会代替用户发送。没有当前对话时创建新乐章。未修改的原图直接沿用原附件，不重编码。原图仍保留在 CAS 中。

## 保存与恢复

草稿按对话和原件摘要隔离，保存完整操作、历史游标和导出编号。每次落笔或历史操作后写入既有 LocalStore；离开前等待保存，失败时留在画页并提供重试。损坏记录不会被空白画稿覆盖。

从对话进入再返回时，阅读锁使用可见条目和条目内偏移恢复位置；跟随最新内容时回到底部。实现依据[官方 Scroller 接口](https://developer.huawei.com/consumer/en/doc/doccenter-references/api/ts-container-scroll/)，不依赖可变高度虚拟列表的累计位移估算。真实中段阅读的进入／返回画面已对照检查。

原图和已完成的马赛克／变换保存实际图像检查点。离线能继续画笔、编号，并在已经收好的检查点间撤销、重做和重新进入；新原图、未缓存检查点、变换和导出需要主机。切换后到达的旧请求不能覆盖新画页。生产产品使用加密 S3 RDB；`preview` 产品依然明确标注关闭后清空，不能据此声称重启持久化已经实测。

照片缓存的实际 JSON 可超过 2 MB。LocalStore 的记录读取改为 `querySqlWithoutRowCount` / `LiteResultSet`，避免普通 ResultSet 的共享内存单行限制；该限制及接口见[官方 RDB 文档](https://developer.huawei.com/consumer/en/doc/harmonyos-references/arkts-apis-data-relationalstore-rdbstore/)。API26 编译已通过，真实加密 RDB 运行与重启恢复仍需设备验证，不能由预览 Map 代替。

## 主机接口

两个端点均使用既有 Bearer 与 `X-Haji-Device` 认证，适用于已配对 companion：

- `POST /api/image-studio/preview`：`{source_id, operations}`，空 `source_id` 表示 1280×1600 草稿纸。返回 `supported,width,height,mime,image_base64`。
- `POST /api/image-studio/export`：另含 `operation_id`，返回标准 Artifact。相同设备、相同编号与相同内容重查返回同一附件；同一编号改传另一份内容返回 409。

每个操作为 `{kind,points,color,width,number}`。`kind` 为 `pen/number/mosaic/rotate/perspective/paper`；点坐标以当前画面左上角为原点、归一化到 0–1。笔宽相对于当前画面短边，颜色为不透明 `#RRGGBBFF`。编号一处、马赛克两个对角、透视四点按左上／右上／右下／左下顺序；透视要求顺时针凸四边形。处理顺序与用户操作顺序相同。

请求最多 400 步、32000 个点，单笔最多 2048 点，旋转／透视／增强合计最多 12 步。输入原件最多 64 MiB，只解码 PNG/JPEG/WebP；头部最多 6400 万像素，JPEG 先尝试解码降采样，实际解码不超过 2400 万像素。处理画面最多 600 万像素、单边 4096。最多两个独立受限进程，各 512 MiB、25 秒；渲染槽和导出锁分别最多等待 2 秒。图片内容不作为代码执行，不接收客户端路径或外部 URL。

预览保持比例，放入 1280×1600 范围；通常 PNG，超过字节预算时使用声明真实 MIME 的 JPEG90。图像字节低于 3 MiB 减 8 KiB，使 Base64 与 JSON 符合既有 4 MiB 中继载荷。导出保留处理分辨率并输出 PNG，不使用预览 JPEG 作为最终原件。

PNG 透明通道保留在编辑结果中；需要 JPEG 预览时只在预览副本合成纸色。已用既有透明书签资源经真实上传和编号导出，实际结果为 RGBA，Alpha 范围仍为 0–255，并带有对应原图摘要。

导出复用 CAS、校验和设备幂等记录。PNG `Description` 包含已有 `hajisaki-ink-v1` 白名单所需的笔迹数量、颜色和实际变换后的范围；另以固定 `HajiSakiEdit` 字段记录原图 SHA256 和操作数量。这些是图像对照资料，不是模型审阅回执或授权。现有文本索引和 ACP 图片输入继续独立处理。中继 connector 仅新增这两个明确路由，未扩大任意路径或主机修改权限。

## 已观察与待完成

已通过真实公共 API 26 编译，并在官方原生预览中实际操作草稿纸落笔、编号、离开重进、照片打开、马赛克、四角拖动、透视、旋转、增强与撤销重做。主机明确停止时，缓存的变换仍能撤销／重做；主机恢复后正常导出。实际 PNG 已检查像素和笔迹元数据，且通过原生输入区发给真实 ACP，模型准确描述了编号和马赛克所在位置。图像与过程记录位于 `tooling/evidence/native-studio-*`。

已复查日间纸边／色环、夜间与 320vp 窄屏布局；导出失败后恢复主机，页内“重试”实际重新导出并回到草稿。同一画稿重复导出返回相同附件 ID，草稿只有一个附件。流式富文本的值快照复用造成实时缺字，现已修复；后续真实流式回复无需重开即可完整显示。主机服务重启后同一对话仍能续写，当前 ACP 登录再次确认可用。

既有 loopback mTLS/AEAD 中继也已实际传递新图片预览接口：请求 `3702ccf7c59b4b909c782822aa96ac80`，认证 200、2364397 字节、`outcome_uncertain:false`，1280×853 实际图片响应。此为 Python 参考传输证据，不是手机 TLS 或外网证明。构建脚本另修正暂存镜像中旧哈希资源的累积；仅确认过期的暂存文件移入回收站，清单在 `runtime/native-stage-recycle-openharmony.json`。

实测使用项目既有资源图，不录制用户摄像头或麦克风，不请求定位。系统照片选择、华为设备签名、真机 RDB 重启恢复、触控延迟、120 Hz 帧率、长时功耗和外网双通道仍需相应条件；上述观察不代替这些原要求。桌面预览的 IME 命令未实际落入中文草稿；不把接口计数当作中文输入实测。中文消息经认证 API 和真实 ACP 完整处理，并已在原生对话显示。

部分额外桌面 Previewer 在收到 SDK 退出命令后记录了访问冲突；相应日志保留。这是桌面 SDK 退出阶段的观察，不能冒充真机退出验收。已配对的主预览与主机服务保留在线。
