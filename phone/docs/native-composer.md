# 常用起笔、乐章语气与上下文整理

原始宪章要求 `/` 呼出模板、切换语气并压缩长上下文。本阶段沿用现有 ArkUI 输入区、真实模型运行、离线存储和受限附件工具。真实原生整理后的续聊已确认上下文下降及事实保留；设备、离线耐久性与完整产品验收仍按原始范围继续。

## 使用与数据合同

输入区点击 `/`，或在正文末尾输入独立的 `/`，进入同一个原生菜单。检索模板后选择，只把真实模板文字放进未发送草稿；原有文字和附件保留，发送仍由用户操作。返回保留草稿和下层阅读位置。模板目录在连接时缓存，供随后离线使用。

“乐章语气”只保存当前乐章的固定选项，不改动全局三轴调音。普通消息及离线待发同时记录发送时选择的语气；服务端把最终语气写进本轮事件，后续设置变化不追改已经排队或送达的消息。历史版本没有该字段时继续兼容原行为。分叉继承当前语气，不把分叉点之后的交接摘要带入旧分支。

“整理长上下文”使用当前模型及档位创建真实运行，原有草稿保持未发送。任务先将当前范围的公开消息、状态和附件标识流式写入原始记录。模型端声明原生整理能力时沿用同一模型会话；不支持时才请求应用交接。原消息和文件均保留。应用交接要求模型完整结束、摘要非空且最多6000字符，摘要、上下文切换和运行完成在一个事务中发布；未达到条件、停止或中断时不发布交接。该路径下一轮从交接及整理之后的新消息创建工作上下文，旧记录仍可从原始文件和历史附件核对。

任务使用固定操作号；手机在请求前保存操作号、模型与档位，响应不确定时沿用同一份请求，避免重复调用模型。关闭菜单与停笔分别处理：任务送达后可关闭菜单回到对话，真正停笔复用现有运行停止接口。控件根据实际运行显示等待、失败和完成，不计算虚假百分比。

MCP仍是既有14工具/v3策略，没有增加任意磁盘、命令或浏览器权限，也没有透传模型端任意斜杠命令。整理属于用户明确发起的产品功能，与会话失败恢复分开；普通工具或网络等待不会触发替换 Codex 聊天。

模型端已声明 `compact` 时，ACP适配器优先调用这一项明确命名的原生命令，继续保留相同模型会话。只记录实际报告的整理前后用量，只有整理后数值下降才发布成功。如果命令正常返回而即时计数尚未下降，显示等待续聊核对；下一次真实普通回复结束后，服务端核对相同模型、档位、会话和实际计数，再发布确认。没有自动追加模型问题或重复整理。启动时可用已有真实回复补齐尚未发布的确认，原先失败状态及事件不改写；接口分别保留 `generation_status` 和最终确认状态。该原生路径不把状态文字当作交接重新注入模型。

## 接口

沿用既有设备认证：

- `GET /api/composer/catalog`：四种常用起笔及五种固定语气。
- `GET /api/conversations/{id}/composer`：当前语气、实际历史状态、最近整理、当前已发布交接及忙碌状态。省略私有模型会话标识。
- `POST /api/conversations/{id}/tone`：`{tone_id}`，仅接受目录中的固定选项。
- `POST /api/conversations/{id}/compact`：`{operation_id,model,effort}`，与普通消息共用同乐章单一活跃运行约束；相同操作号和参数返回同一次运行。
- 普通 `POST .../messages` 增加可选 `tone_id`。重复客户端编号校验指定语气，缺省的旧请求保持兼容。

上述目录、状态、语气及整理路径已加入现有中继白名单。新增表为 `conversation_tones`、`context_compactions`、`conversation_contexts`，完整导出包含这些表及所引用的运行。确认记录包含原生命令前后实际用量和 `verification_run_id`。真实归档走原有CAS与分段完成流程，没有临时文件副本。
