# 选文附页与同题对照

本阶段对应原始宪章的精准选文、Thread子线程及双模型/思考档位盲选。选文与真实附页续聊已有实际证据；对照设置已检查，双方生成和投票仍未完整验收。用户要求尽快收尾，本轮按实际完成情况交付。

## 选文与附页

回复保留“引用”全文入口，新增“选文”。独立选文页展示服务端从真实公开回复提取的文字，保留段落、代码内容和比较符号；原生只读Text支持长按与拖动跨段选择。底部操作使用实际选区，不从剪贴板读取，也没有可任意改写来源的输入框。所用选择回调见[华为Text文档](https://developer.huawei.com/consumer/en/doc/harmonyos-references/ts-basic-components-text/)。

“引用选文”将片段放入未发送草稿，原有文字、附件保留。“开附页”创建空的独立乐章，不自动向模型提问。服务端核对原消息归属、公开内容SHA及所选文字，记录来源、原句、创建时的有界历史/锚点/待办快照和当前语气；原乐章消息及模型会话不改写。新页首次真实提问才把这些资料交给模型，后续沿用本页会话。原句在聊天顶部，返回可到原乐章；同次应用内保留阅读锚点及模型选择。

手机在提交前保存固定操作号及完整请求，网络不确定时重试同一份。服务端在事务中再次核对编号；同编号同参数返回同一附页。已知拒绝后允许重新取文。原件授权限于快照中实际分享或钉选的文件，以及所引用消息的原件，不开放其他会话或任意磁盘。生产存储仍是既有加密RDB，临时预览的内存缓存不等于设备重启耐久性。

## 对照的数据与操作

“分支”页按原乐章保存附页和对照历史。创建对照复制本次题目和原件，保留原输入区草稿；从真实模型目录选两种不同的模型/档位，同一份创建时上下文、长期记忆和调音交给两侧。A/B由服务端随机分配，在投票或主动揭晓之前不返回模型及档位元数据。

手机左右滑动阅读两份回答，分别保留上翻位置。直连复用现有认证SSE，每侧有自己的进度水位，12ms合并到达的事件，在缓存提交后更新；断线或备用中继改用真实快照补齐。离开界面不会停止主机任务，重新进入读取实际结果。保存的对照只展示本次原始回答，之后在某侧继续聊天不会改写投票对象。

创建请求保存固定编号，部分准备只接续缺少的运行；已完成的回答不重做。停止会记录本次对照已停下，只停止仍活跃的运行，随后重试创建不会启动原先未开始的一侧。投票须等两侧终止，写入选择后揭晓身份；“继续这一页”以该侧实际模型/档位打开普通聊天。明确停下的部分回答不被冒充为完整结果。

新增数据表是conversation_threads、arenas、arena_sides和branch_artifacts；完整导出包含这些表及所关联的既有消息、运行、文件。MCP工具集合与既有14工具/v3策略保持一致。新增系统事件model_configured仅记录实际协商的模型/档位，不存私有思考内容。
