# 原生文件翻阅

手机从真实附件卡片进入原生文件页，返回到原来的页面；原件保存仍走独立设备凭据与完整字节/摘要核验。文字与源码沿用原有阅读器。新二进制阅读器没有借用浏览器画面，也没有向Web组件传入主机钥匙。

## 数据与边界

- PDF：主机`/api/artifacts/{id}/page-image`在独立进程中解析一张真实纸页，客户端以ArkUI Image显示。按原件摘要与页码缓存，保留页码、100–300%放大倍率；原色/柔光切换及原生双向滚动。现有公共SDK没有华为PDF Kit，ArkWeb在桌面预览器不支持；此路径是主机解析与原生显示，不声称设备端PDF解析或文字选择已完成。没打开过的纸页仍需要主机，原始PDF另行保存。
- 工作簿：`/api/artifacts/{id}/sheet`每次提供20行真实数据，支持切换工作表、分页、单元格换行、固定首列/表头和横向同步滚动。原始值不执行公式，显示有限原件样式。按当前字体和列宽测量行高；工作表与行页位置按原件摘要记住。夜间默认柔光，可切换原色。
- ZIP：复用`/api/artifacts/{id}/text?page=...&limit=20`读取经过安全核验的真实目录，显示条目名、目录/字节数、总项数与展开大小，不执行或解出包内文件。目录支持分页缓存。

PDF与XLSX的当前单次解析原件上限为64MiB；原件上传/保存的容量合同与解析合同分开。PDF解析最多2个并行进程，每个384MiB、20秒；请求宽度不超过2048像素，像素面积不超过600万。通常返回PNG；超过图像字节预算的照片页使用同像素尺寸的JPEG90并声明真实MIME。图像字节上限为3MiB减8KiB，给Base64和JSON留出空间，使其符合既有4MiB加密中继载荷限制。没有改写PDF原件。

页缓存与阅读位置使用既有LocalStore：生产产品仍为加密S3 RDB，临时预览产品仍明确提示关闭后清空。只有实际取得并成功存入的页可离线重开；写入失败有单独提示，不能把内存预览算作重启耐久性。大文档、全部媒体离线、原生PDFKit/ArkWeb设备能力和性能指标继续保留在总验收台账中。

## 配对与工具

`tools/enroll_companion.py`通过本机owner API签发一把独立companion钥匙，写入私有文件；预留中的回执或已有文件会阻止盲目重复签发。脚本不会打印令牌。手机表单填设备编号与该设备的令牌，不复制主机引导钥匙。它不证明硬件指纹或生物识别批准。

`tooling/capture_pdf_pages.py`只保存实际纸页接口返回的图像，用于逐页视觉检查；没有断言或功能遍历。应用运行本身不依赖这个工具或Codex。所有派生图像均可追溯到仍在CAS中的原始PDF。

中继connector明确允许`sheet`和`page-image`两条认证读取路径及其`sheet`/`width`参数，既有路径、鉴权与载荷限制不变。这只是代码合同整合，实际证书导入、外网双通道与TLS负向验证尚未完成。

PDF读取的直连等待预算为45秒，覆盖最长20秒排队和20秒解析；其他普通JSON请求保持原有20秒，中继沿用50秒。文件页的实际网络成功或最终网络/401失败会反馈给主界面连接状态；命中本地缓存不会被算作重新联网。断网提示针对文件阅读，保留当前成功取得的页码与内容。

## 当前观察

真实六页交接PDF的主机纸页已逐页查看，均为2048×2897像素；实际XLSX与ZIP来自同一模型交付链。公共API26常规包与临时预览包均完成真实编译。原生已观察真实ZIP目录、表格内容/第二页/固定表头首列/工作表切换与长格；修复了切表后固定列标题未更新和夜间菜单过亮。PDF已实际翻页、放大、切换原色与输入页码跳页。

另将既有官方工具链ZIP通过Studio真实上传后在原生打开：48项、27,725,579原始字节、46,742,041展开字节，正常翻到1–20、21–40、41–48。原始压缩包与服务端SHA256一致；未新造夹具或放宽检查限制。

双向平移修正后已实际复查。主机明确停止时，目录、工作表和PDF已打开页都能重开；未缓存页失败保留原页。恢复主机后同一重试按钮取到真正的新页，并恢复连接灯。具体画面/过程见总验收台账。以上仅证明当次临时预览的业务路径，原生系统文件保存、生产RDB重启耐久性和设备性能仍需真实条件验证。

当前两份未签名HAP已重打包到`releases/`，分别63,297,914与63,298,514字节；摘要见对应清单，包含实际Ark字节码及完整123份离线渲染资源。新包同时包括备用通道导入与设备绑定路径，其验收边界另见`native-relay-import.md`。

## 原件保存续查

保存使用独立设备凭据，将收到的字节写入私有文件，完整大小与SHA256核验后才调用系统DocumentViewPicker。写入显式传入偏移与长度；返回字节数必须有效且前进。失败保留阶段，不把写入、校验或系统窗口失败统称为下载失败。阅读页的“重试”会重做保存；档案卡片保存期间防重复触发；原音页也保留相同文件错误。取消系统选择不会被显示为已保存。

实际在当前桌面Previewer保存同一修订PDF与既有`jfk.flac`：首个16KiB块的写入返回0，没有数值平台错误码，显式长度仍如此；运行进程未加载`libfs.dll`。这只是当前环境的具体观察，不据此推断真机行为。HDC当前没有设备。未进入系统保存窗口、未产生可核对的导出原件，因此系统导出与取消仍不能算通过。读取纸页与缓存不是原件保存的替代证据。

最终编译后的阅读页保存及同一“重试”均实际触发写入，并保留第2页/150%：`tooling/evidence/native-save-accepted-reader.png`与`native-save-accepted-retry.png`已查看。原音与档案两处错误布局也已查看。只读SDK入口`tooling/native_runtime_info.py`保留显式ASCII路径，避免HDC解析回中文目录后的路径警告；`runtime/native-runtime-capabilities-ascii.txt`为无该警告、退出0的设备查询。其中Previewer帮助输出异常没有被当作能力清单或模型会话失败。
